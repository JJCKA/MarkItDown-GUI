# 技术架构文档

## 系统架构

MarkItDown GUI 是一个 Electron 桌面应用，前端 React + TypeScript，后端 Python FastAPI。三层结构：

```
┌─────────────────────────────────────────┐
│           Electron 壳                    │
│  ┌─────────────────────────────────┐    │
│  │     React 前端 (TypeScript)      │    │
│  │  Zustand 状态管理 · marked 渲染  │    │
│  └──────────┬──────────────────────┘    │
│             │  HTTP (localhost:随机端口)  │
│  ┌──────────▼──────────────────────┐    │
│  │   Python FastAPI 后端            │    │
│  │   markitdown · LLMClient        │    │
│  │   CacheManager · Config         │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

## 前端架构

### 技术选型

| 技术 | 用途 |
|------|------|
| React 18 + TypeScript | UI 框架 |
| Zustand | 全局状态管理 |
| marked | Markdown → HTML 渲染（自定义渲染器支持任务列表、代码语言标签） |
| CSS 变量 | Typora 极简主题 |

### 状态管理 (Zustand)

`appStore` 集中管理：

- **视图状态**：`view`（editor/settings/history/stats）、`viewMode`（preview/source）、`compareVisible`
- **文件**：`rootPaths`、`treeItems`、`selectedPaths`、`convertedPaths`
- **转换**：`results` Map、`activeResult`、`progress`、`isConverting`
- **队列**：`queueItems`、`queueVisible`
- **日志**：`logs`、`logVisible`
- **历史/缓存**：`historyItems`、`skipAutoSelect`
- **统计**：`stats`（持久化到 localStorage）
- **UI**：`sidebarWidth`、`sidebarVisible`、`showLLMPopup`

### 拖拽支持

`App.tsx` 监听 `onDragEnter`/`onDragOver`/`onDrop` 事件，使用 `dragCounter` ref 跟踪嵌套拖拽。拖放时通过 `file.path`（Electron 特有属性）获取文件路径，调用 `addRootPaths()` 添加到文件树。

### 后端通信

`src/api/client.ts` 通过 `window.electronAPI.getBackendPort()` 获取动态端口，以 HTTP + SSE 与后端通信。单文件转换用 JSON 请求/响应，批量/LLM 转换用 SSE 流式推送进度。

## 后端架构

### 模块结构

```
backend/
├── main.py              # FastAPI 应用 + 健康检查 + 导出（含缓存更新）
├── api/
│   ├── convert.py       # /api/convert/* 端点（含 SSE）+ 历史/缓存写入
│   └── settings.py      # /api/settings/* 端点（含缓存管理）
├── core/
│   ├── config.py        # JSON 持久化配置（~/.markitdown-ui/config.json）
│   ├── cache.py         # 转换结果缓存（~/.markitdown-ui/cache.json）
│   ├── converter.py     # 转换引擎（基础 + LLM 增强 + 图片提取 + 分块）
│   ├── llm_client.py    # OpenAI 兼容 API 客户端
│   └── doc_converter.py # .doc → .docx（COM 自动化）
├── prompts/
│   └── builtin.py       # LLM Prompt 模板 + 扩展名分类
└── tests/
    ├── test_config.py
    ├── test_converter.py
    └── test_prompts.py
```

### 转换数据流 (LLM 增强)

```
用户点击 [LLM 转换]
  → BottomBar.handleConvert(true)
  → api.convertFile(path, useLlm=true)
  → POST /api/convert/llm
  → Converter.convert_with_llm(path)
    ├─ Step 1: 基础转换 (markitdown) → 保存为 raw_markdown
    ├─ Step 2: 图片描述 (LLM vision)
    ├─ Step 3: 音频转录 (LLM)
    ├─ Step 4: 表单清洗 (LLM, 分块处理)
    └─ Step 5: 全文分析 (LLM, 分块处理)
  → config.add_history(元数据) → config.save()
  → cache.put(markdown, raw_markdown) → cache.save()
  → 返回 { markdown, raw_markdown, ... }
  → BottomBar 调用 api.getHistory() 刷新历史列表
  → App.useEffect 更新 activeResult → 渲染预览
```

### 数据持久化

| 数据 | 存储位置 | 格式 |
|------|----------|------|
| 配置 | `~/.markitdown-ui/config.json` | JSON（Config 类） |
| 历史记录 | `config.json` 的 `history.items` | JSON 数组（仅元数据） |
| 转换缓存 | `~/.markitdown-ui/cache.json` | JSON 数组（含 markdown 内容） |
| 转换统计 | `localStorage` | JSON（前端持久化） |

历史记录和缓存分离：历史记录只存元数据（文件名、成功/失败、字符数、耗时、时间戳），缓存存完整的 markdown 内容。`get_history` 端点自动将两者合并返回。

### 配置系统

`Config` 类基于 JSON 文件持久化，支持点号路径读写 (`llm.api_key`)。深度合并策略保证新增字段有默认值。每次请求前调用 `config.load()` 确保读取最新设置（解决多实例内存不同步问题）。

`CacheManager` 类管理单一 `cache.json` 文件，所有缓存集中存储。支持 `max_items` 限制，超出时自动淘汰旧条目。

### 线程模型

FastAPI 异步事件循环驱动所有 LLM 调用。同步的基础转换通过 `run_in_executor` 放入线程池，避免阻塞事件循环。SSE 端点通过 `AsyncGenerator` 流式返回进度。

## 打包架构

```bash
scripts\build.bat
  ├─ vite build              → dist/ + dist-electron/
  ├─ PyInstaller backend/    → release/markitdown-backend.exe
  └─ electron-builder        → release/MarkItDown GUI.exe
```

运行时 Electron 优先查找 `resources/backend/markitdown-backend.exe`（打包环境），其次项目内的 `MDGUI/Scripts/python.exe`（开发环境）。
