# 技术架构文档

## 系统架构

MarkItDown GUI 是一个 Electron 桌面应用，前端 React + TypeScript，后端 Python FastAPI。三层结构：

```
┌─────────────────────────────────────────┐
│           Electron 壳                    │
│  ┌─────────────────────────────────┐    │
│  │     React 前端 (TypeScript)      │    │
│  │  Zustand 状态管理 · marked 渲染  │    │
│  └──────────┬──────────────────────┘    │
│             │  HTTP (localhost:随机端口)  │
│  ┌──────────▼──────────────────────┐    │
│  │   Python FastAPI 后端            │    │
│  │   markitdown · LLMClient        │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

## 前端架构

### 技术选型

| 技术 | 用途 |
|------|------|
| React 18 + TypeScript | UI 框架 |
| Zustand | 全局状态管理 |
| marked | Markdown → HTML 渲染 |
| CSS 变量 | Typora 极简主题 |

### 组件树

```
App
├── TitleBar          # 标题栏 + 窗口控件 + 拖拽
├── MenuBar           # 文件 编辑 视图 转换 帮助
├── Sidebar           # 侧边栏容器
│   ├── TabBtn        # 文件 / 已转换 标签
│   ├── FileTree      # 文件树（SVG 图标 + 展开/折叠）
│   └── ConvertedList # 已转换列表
├── Main Content
│   ├── MarkdownViewer # 预览/源码 + 复制/导出
│   ├── SettingsPage   # LLM 配置 + 功能开关
│   ├── HistoryPanel   # 转换历史
│   ├── LogPanel       # 折叠日志
│   └── BottomBar      # 控制栏（图标 + 转换按钮）
└── LLMPopup          # LLM 功能弹窗
```

### 状态管理 (Zustand)

`appStore` 集中管理：视图状态、文件树、转换结果 Map、进度、日志、设置面板状态、侧边栏宽度/可见性、源码/预览模式。

### 后端通信

`src/api/client.ts` 通过 `window.electronAPI.getBackendPort()` 获取动态端口，以 HTTP + SSE 与后端通信。单文件转换用 JSON 请求/响应，批量/LLM 转换用 SSE 流式推送进度。

## 后端架构

### 模块结构

```
backend/
├── main.py              # FastAPI 应用 + 健康检查 + 导出
├── api/
│   ├── convert.py       # /api/convert/* 端点（含 SSE）
│   └── settings.py      # /api/settings/* 端点
├── core/
│   ├── config.py        # JSON 持久化配置
│   ├── converter.py     # 转换引擎（基础 + LLM 增强）
│   ├── llm_client.py    # OpenAI 兼容 API 客户端
│   └── doc_converter.py # .doc → .docx（COM 自动化）
├── prompts/
│   └── builtin.py       # LLM Prompt 模板 + 扩展名分类
└── tests/
    ├── test_config.py
    ├── test_converter.py
    └── test_prompts.py
```

### 转换数据流 (LLM 增强)

```
用户点击 [LLM 转换]
  → BottomBar.handleConvert(true)
  → api.convertFile(path, useLlm=true)
  → POST /api/convert/llm
  → Converter.convert_with_llm(path)
    ├─ Step 1: 基础转换 (markitdown)
    ├─ Step 2: 图片描述 (LLM vision)
    ├─ Step 3: 音频转录 (LLM)
    ├─ Step 4: 表单清洗 (LLM, 分块处理)
    └─ Step 5: 全文分析 (LLM, 分块处理)
  → 结果写入 ~/.markitdown-ui/config.json 历史
  → App.useEffect 更新 activeResult → 渲染预览
```

### 配置系统

`Config` 类基于 JSON 文件持久化，支持点号路径读写 (`llm.api_key`)。深度合并策略保证新增字段有默认值。每次转换前调用 `config.load()` 确保读取最新设置。

### 线程模型

FastAPI 异步事件循环驱动所有 LLM 调用。同步的基础转换通过 `run_in_executor` 放入线程池，避免阻塞事件循环。SSE 端点通过 `AsyncGenerator` 流式返回进度。

## 打包架构

```bash
scripts\build.bat
  ├─ vite build              → dist/ + dist-electron/
  ├─ PyInstaller backend/    → release/markitdown-backend.exe
  └─ electron-builder        → release/MarkItDown 2.0.0.exe
```

运行时 Electron 优先查找 `resources/backend/markitdown-backend.exe`（打包环境），其次项目内的 `MDGUI/Scripts/python.exe`（开发环境）。
